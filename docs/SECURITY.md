# Безопасность фронтенда

Что уже сделано на стороне браузера, как это проверить и что нельзя закрыть без бэкенда.

## 1. Заголовки и CSP (`vercel.json`)

Единственный источник правды — [`vercel.json`](../vercel.json). Эти же заголовки подключаются к `npm run preview`, поэтому CSP можно проверить локально до деплоя.

| Заголовок | Зачем |
|---|---|
| `Content-Security-Policy` | Скрипты, стили, шрифты, картинки и запросы — только с нашего домена. Единственное исключение — `frame-src https://www.youtube-nocookie.com` для видео. Запрещены `unsafe-eval` и инлайн-скрипты, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`. |
| `Strict-Transport-Security` | Браузер всегда ходит по HTTPS (1 год, с поддоменами). |
| `X-Content-Type-Options: nosniff` | Браузер не «угадывает» тип файла. |
| `X-Frame-Options: DENY` | Сайт нельзя встроить в чужой `<iframe>` (защита от clickjacking; дублирует `frame-ancestors`). |
| `Referrer-Policy: strict-origin-when-cross-origin` | Наружу уходит только домен, без путей и параметров. |
| `Permissions-Policy` | Отключены камера, микрофон, геолокация, платежи, USB, датчики; автозапуск и полноэкранный режим — только для YouTube. |
| `Cross-Origin-Opener-Policy: same-origin` | Изоляция окна от других сайтов. |
| `Cache-Control` для `/assets/*` | Хэшированные файлы кэшируются навсегда. |

**Осознанные компромиссы CSP**

* `style-src-attr 'unsafe-inline'` — библиотека анимаций (`motion`) выставляет инлайн-стили (`style="transform: …"`). Это разрешает только *атрибуты* style; `<style>`-теги и внешние стили остаются под `style-src 'self'`. Скрипты это не затрагивает.
* `zod` настроен с `jitless: true` ([`src/app/zodConfig.ts`](../src/app/zodConfig.ts)) — иначе он пробует `new Function`, что строгий CSP репортит как нарушение.
* HSTS без `preload`. Включать `preload` стоит, только когда сайт окончательно на своём домене.

**Если добавляете внешний сервис** (аналитика, карта, капча) — сначала добавьте его домен в нужную директиву CSP (`script-src`, `connect-src`, `frame-src`), иначе браузер его заблокирует. Тест `tests/headers.test.ts` намеренно упадёт, если в CSP появится новый внешний источник, — это повод осознанно обновить тест.

## 2. Формы

Три формы (демо, сообщение, подписка) используют общие защиты:

* **Строгое поле телефона** (`PhoneField`, `shared/lib/phone.ts`): набрать можно только цифры — буквы и символы не вводятся и не вставляются, номер сам форматируется в `+38 050 123 45 67`, больше 10 цифр после `+38` не набрать. В схеме принимается только украинский номер (`0XXXXXXXXX` / `+380XXXXXXXXX`), на выходе — `+380501234567`.
* **zod-валидация** (`shared/lib/validation.ts`): формат имени, e-mail; максимальные длины (те же значения стоят в `maxLength`); в сообщении — не больше 2 ссылок.
* **Очистка текста** (`shared/lib/sanitize.ts`): убираются нулевые и управляющие символы, zero-width и bidi-символы (подмена направления текста), схлопываются пробелы.
* **Honeypot** — скрытое поле `website`. Если его заполнили (боты заполняют всё подряд), форма делает вид, что всё прошло, но ничего не отправляет.
* **Минимальное время заполнения** — отправка быстрее 1,5 с после появления формы отклоняется.
* **Лимит отправок** — не больше 3 на форму за 10 минут (`shared/lib/rateLimit.ts`, `sessionStorage`).
* Данные из форм нигде не выводятся как HTML.

> ⚠️ Это защита от случайных повторов и примитивных скриптов. Целенаправленного атакующего она не остановит: honeypot и таймер обходятся, `sessionStorage` очищается. Реальная защита должна быть на сервере (см. раздел 5).

## 3. Защита от XSS

* Контент статей хранится структурированно (абзац / заголовок / картинка) и выводится React-элементами; React экранирует всё сам.
* ESLint **запрещает** `dangerouslySetInnerHTML`, присваивание `innerHTML` / `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`, `javascript:`-ссылки. Нарушение ломает `npm run lint`.
* Данные, которые придут с бэкенда, проходят через zod-схемы: адреса картинок должны быть своим путём, `https:` или `data:image/(png|jpeg|webp|gif|avif)` — `javascript:`, `data:image/svg+xml`, `//host` и `http:` отклоняются (`shared/lib/safeUrl.ts`).
* Параметры адресной строки — недоверенный ввод: `slug` проверяется регуляркой до запроса (`/blog/<script>` сразу ведёт на 404), `?category=` сверяется со списком разрешённых значений.
* Внешние ссылки открываются с `rel="noopener noreferrer"`.
* YouTube-плеер: домен `youtube-nocookie.com`, подгружается только по клику, `<iframe sandbox>` без права менять адрес верхней страницы.

## 4. Зависимости

* `npm run audit:prod` — проверка продакшен-зависимостей (падает на high и выше). Сейчас: **0 уязвимостей**.
* Известные замечания `npm audit` (moderate) относятся только к инструментам разработки (`typescript-eslint → minimatch`), в браузер пользователя они не попадают.
* `.github/dependabot.yml` раз в неделю присылает PR с обновлениями.
* Версии зафиксированы в `package-lock.json` — всегда ставьте через `npm ci` в CI.

## 5. Что невозможно закрыть на фронтенде (нужен бэкенд / сервис)

1. **Серверная валидация** тех же полей — клиентской проверке доверять нельзя.
2. **Капча** (Cloudflare Turnstile, hCaptcha, reCAPTCHA) на формах — единственное надёжное средство против ботов. После подключения добавьте домен капчи в CSP (`script-src`, `frame-src`, `connect-src`).
3. **Rate limiting** по IP/сессии на сервере.
4. **Вход и сессии** (кнопки «Вход» / «Регистрация» пока открывают форму заявки): токены только в `HttpOnly; Secure; SameSite=Lax` cookie, CSRF-токен для изменяющих запросов, никаких токенов в `localStorage`.
5. **Секреты.** Всё, что начинается с `VITE_`, попадает в браузер. Ключи и пароли в переменные окружения фронтенда класть нельзя.
6. **Мониторинг CSP**: заголовок `report-to` / `Content-Security-Policy-Report-Only` с отправкой отчётов на собственный эндпоинт.

## 6. Как проверить

```bash
npm run lint        # правила против опасных API
npm test            # тесты валидации, очистки, лимита отправок, URL и заголовков
npm run build && npm run preview
curl -I http://localhost:4173/    # заголовки безопасности
```

Для ручной проверки CSP: откройте `npm run preview`, DevTools → Console. Любое нарушение политики видно как `Refused to … because it violates the following Content Security Policy directive`.

После деплоя проверьте сайт на [securityheaders.com](https://securityheaders.com) и [Mozilla Observatory](https://developer.mozilla.org/en-US/observatory).
